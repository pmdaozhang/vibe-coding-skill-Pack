# 文档分级规则

## A 级（完整文档流程）
新功能、架构变更、接口变更、数据模型变更
→ 建 features 文档 + test-cases 文档 + 更新 ROADMAP

## B 级（轻量文档）
Bug 修复、UI 微调、文案修改
→ 更新 CHANGELOG + 在相关 feature 文档追加变更记录

## C 级（仅 git commit 信息）
注释修改、格式化、重命名（不改行为）

## 需求文档格式（features/）
每个功能一个文件：编号-功能名.md
包含：需求描述、设计决策、验收标准、变更记录、关联文件

## 测试用例格式（test-cases/）
每个功能一个文件：编号-功能名.md
包含：正常场景、边界场景、异常场景、回归范围

## 代码与文档一致性
- 开工前先读对应功能的文档
- 需求变更时：文档版本 +1 → 追加变更记录 → 同步改代码和测试
- 代码文件头部标注功能编号
- 禁止只改代码不改文档
